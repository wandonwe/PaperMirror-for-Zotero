# 5.0.0 架构升级审阅

日期：2026-11-23　范围：`v4.10.2..1fbd0a5`，52 个提交，110 个文件，+7.5k / −2.3k 行（含测试、夹具与文档）。

## 结论

可以发布。结构层的方向是对的，并且已经在真机数据上体现出来：随机抽样每轮需要新增的特例规则从重构前的 5–6 条降到 2–3 条，同一页的结构不再随翻页顺序变化。审阅中没有发现阻断发布的缺陷；一处重复定义已在本次合并（见「已处理」），文档与发布说明已补齐。剩下的是 5.1 应该处理的结构性欠账，列在最后。

## 逐项审阅

**1. 全篇样式与单页流水线**（`documentStyle.ts`、`pagePipeline.ts`）
- 好：全篇事实只算一次，参考文献范围能结束、可多段；单页函数没有会话状态，语料工具与插件得出同样的块，能离线回归。
- 风险：预读每篇最多 400 页、4 页并行，打开大文献时有额外 CPU 开销；首次抽取最多等 6 秒。超过 400 页的文档没有全篇样式，r23 的 774 页教科书因此在真机上与语料结果不同（已为「页顶 BIBLIOGRAPHY 的条目页」补了逐页规则）。
- 建议（5.1）：超过上限时按需抽样（目录附近、末 15% 页）而不是整体放弃。

**2. 断段打分与局部版面模型**（`paragraphHeuristics.ts`、`spanBlockBuilder.ts`）
- 好：打分与旧规则逐例等价后才替换（768 种组合穷举、语料零差异），之后的每项修复都附理由和回归测试。
- 风险：`spanBlockBuilder.ts` 1840 行、`paragraphHeuristics.ts` 1250 行，仍是全仓库最大的两个结构文件；源码里有 44 处「校验 rNN」注释指向具体文献，作为出处很有用，但说明规则仍在按样本累积。
- 文本层没有字重，粗体 / 斜体小节标题并进段落是同一类遗留问题，靠版面规则补不完。
- 建议（5.1）：把「行 → 段」的证据收集与「列表 / 索引 / 缩略语 / 联系人」这类区域识别拆成独立模块；在提取层取字体名里的 Bold / Italic 作为小标题证据。

**3. 参考文献识别与验收**（`referenceDetect.ts`、`translationValidation.ts`、`referenceAlignment.ts`）
- 好：结构侧（认条目）与验收侧（作者原样、年份仍在、不只剩标题）用同一套形态定义，r23 真机复测证明两侧都要有：结构认出条目后，模型仍可能只译标题。
- 已处理：姓氏前缀表与连写年份的正则在三处各定义了一份，本次合并为 `referenceDetect` 的 `SURNAME_PARTICLES` / `YEAR`。`tableStructure.ts` 的 `CITATION_LABEL` 和验收侧另一份前缀表（含 bin / ibn）语义不同，暂不合并。

**4. 符号恢复**（`embeddedFontSymbols.ts`、`symbolFontSemantics.ts`）
- 好：坚持「只凭字形轮廓、不看字体名」；运算符位只查本页画字少的字体、不做整页替换，31 篇语料扫描零误报。
- 风险：每页多解析几个小字体，有一次性开销（按字体缓存）。

**5. 缓存与升级成本**（`promptPolicies.ts`、段落库键）
- 好：以后改一条规则只让相关的块失效。
- 升级成本：结构变化导致分块不同的段落不能沿用旧译文。按本机语料估算约 16% 的可译段落（9% 的字符）文本发生变化，再加参考文献与人名规则升版涉及的块（约占可译块 23%，两者有重叠），合计约 1/4 到 1/3 的旧段落会重译一次。已写进发布说明。

**6. 翻译管理器与会话**（`pageRun.ts`、`pageLedger.ts`、`translationManager.ts`、`readerSession.ts`）
- 好：重构分 12 步、每步「行为不变」并有屏蔽网络的缓存验证；账本把三次出过缺陷的压缩在飞标记收成显式状态机，顺带修掉一处递归 finally 清错代的潜在缺陷。
- 风险：`translationManager.ts`（3444 行）与 `readerSession.ts`（3804 行）仍过大。
- 对冲请求：只在用户配置了多个引擎时启用，备选请求经过同样的端点准入（仅本地模式下不会发往云端）和并发名额，诊断记录次数。代价是偶尔多一次请求额度，已在说明中写明。

**7. 引擎与型号**（`modelCatalog.ts`、`modelMigrations.ts`、`providerAvailability.ts`）
- 型号资料核对于 2026-11-19。本次审阅抽查 OpenAI 停用页与 Claude Sonnet 4.5 退役日期，与代码一致（gpt-5 系列 12 月 11 日、gpt-4.1 系列 2027-01-14、claude-sonnet-4-5 2026-11-30）。gpt-4.1-nano 的官方建议替代是 gpt-5.6-luna，代码迁到更新的 gpt-6-luna，属可接受的选择。
- 只按服务商公布的日期迁移、代理和网关不改，迁移会改变用户的计费型号，说明里已列出。
- `providersWithSavedKeys` 只查「有没有」密钥、不取值，凭据库超时退回已知来源，不卡菜单。

**8. 隐私与安全**
- 诊断新增字段都是数字（documentStyleState、referencesFirstPage 等），遵守既有隐私闸。
- 语料工具与回归夹具：PDF 和输出放在仓库外；仓库里只有合成文本，或把字母换成 x/X、数字换成 0 的版面几何。

## 5.1 建议

1. 超过 400 页的文档按需抽样建立全篇样式。
2. 提取层带上字重 / 斜体证据，解决小节标题并段。
3. 拆分 `spanBlockBuilder.ts`（区域识别独立）、`translationManager.ts` 与 `readerSession.ts`。
4. 数学字体里画在拉丁字母位置上的希腊字母（μ、α）：需要比运算符更强的证据，先做语料统计。
5. 表格单元格翻译时带上行 / 列标题作为上下文（型号名被直译）。
