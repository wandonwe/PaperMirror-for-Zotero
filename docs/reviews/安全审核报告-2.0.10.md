# PaperMirror for Zotero 2.0.10 — 安全专项审核(隐私与密钥)

- 审核对象: 版本 2.0.10(提交 194abf7)
- 范围: API 密钥全生命周期、日志/诊断/UI 泄露面、网络出站与本地桥接、持久化与内存痕迹
- 方法: 四维度并行审计 + 以密钥值/论文文本为污点源的手工污点追踪;关键发现在源码逐一复核并对 sanitizer、桥接实测复现(标【已复现】)
- 定位: 这是**主动加固**审核。BYOK 五条硬承诺在插件(TypeScript)侧整体成立且此前九版无回归;本轮发现集中在 (1) sanitizer 模式清单的覆盖缺口、(2) 本地桥接脚本 `babeldoc_server.py` 的无认证攻击面。

## 1. 一句话结论

没有 P0。最要紧的是两组: **日志脱敏器对 URL 内密钥与几类新密钥形状完全失明**(P1,直接抵消 2.0.10 的 diagnose 整体脱敏),以及**本地桥接无认证 + filename 路径遍历**(P2 组合成「恶意网页→本地任意文件写入→代码执行」的完整链)。其余为纵深加固级。攻击者模型: A=同机他用户 · B=profile 备份/云同步 · C=恶意翻译服务 · E=拿到诊断/截图的人 · F=本机恶意网页/同机他用户(对桥接)。

## 2. P1(高)

| 编号 | 摘要 | 位置 | 攻击者 |
|---|---|---|---|
| S1【已复现】 | **sanitizer 对 URL 内密钥与 AIza/裸 key= 失明 → diagnose 整体脱敏形同虚设** | `security/logSanitizer.ts:6-19`;泄露出口 `lifecycle/startup.ts:226`、`preferences.ts:580/588` | E |

实测(真实模式清单):`base URL: …?key=AIzaSyD…` → **原样输出**,7 条模式无一命中;裸 `?key=supersecretvalue123` → **原样输出**(只有 `api[_-]?key` 前缀被覆盖,`key=` 不被)。根因两条叠加: (a) Gemini 官方 REST 就是 `?key=` 用法,这类密钥**只存在于 Base URL 字符串里,从不经过 registerSecret**(注册只在 getApiKey/setApiKey),精确替换救不了;(b) AIza / Groq `gsk_`(裸文,非 auth 头时)/ 智谱 `hex.suffix` 形状不在模式清单。2.0.10 的 `diagnose()` 整体 sanitize 的注释明写目标就是防「Base URL 里被放了 ?key=」——**该目标未达成**。同根出口还有 preferences 的「实际请求地址: ${url}」直接上屏(UI 不过 sanitizer)。

修复: 补四条模式并保留参数名替换值 —— `/AIza[0-9A-Za-z_-]{30,}/g`、`/gsk_[A-Za-z0-9_-]{20,}/g`、智谱 `/\b[0-9a-f]{32}\.[A-Za-z0-9]{8,}\b/g`、通用 URL 凭据 `/([?&](?:key|api_?key|token|access_token)=)[^&\s"']{6,}/gi`;并在保存 provider profile 时解析 Base URL/apiPath 的查询参数值 registerSecret(结构性兜底)。

## 3. P2(中)

| 编号 | 摘要 | 位置 | 攻击者 |
|---|---|---|---|
| S2【已复现】 | **桥接 filename 路径遍历 → 任意文件写入** | `tools/babeldoc_server.py:110` | F |
| S3【已复现】 | **桥接无 Host/Origin 校验 → 恶意网页 CSRF / DNS-rebinding** | `tools/babeldoc_server.py:178-230` | F |
| S4 | **桥接无认证 + 密钥经 localhost 明文 socket → 同机端口抢占窃密** | `pdfService.ts:138-153` → `babeldoc_server.py:190` | A/F |
| S5【已复现】 | **sanitizer 重叠密钥部分泄露: 长密钥只被替换成 `[REDACTED]+残余后缀`** | `security/logSanitizer.ts:55-58` | E |

- **S2**: `os.path.join(work, req.get("filename"))` 直接用请求体的 filename,内容是攻击者可控的 base64。绝对路径或 `../` 逃逸出 mkdtemp 工作目录 → 以桥接进程 uid 的**任意文件写入原语**(覆盖 `~/.bash_profile`/`~/.zshrc` → 本地代码执行)。插件自身合法路径已取 basename(readerSession.ts:1784 安全),但服务端绝不能信任客户端。修复: 服务端强制 `os.path.basename(filename)` 并拒绝空/`.`开头/含分隔符者;或忽略该字段固定用 `input.pdf`。
- **S3**: 桥接只绑 127.0.0.1 但对 Host/Origin/Referer 零校验、无 CORS、无令牌。受害者浏览任意网页时,页面 JS 可发「简单请求」POST(text/plain,无预检)到 `http://127.0.0.1:11017/translate` —— 写副作用(S2 的任意写)不需读响应即可远程触发;DNS-rebinding 进一步可绕过 SOP 读 `/status`、`/result`(含译文 PDF)。修复(防 rebinding 关键): 校验 Host 头必须为 `127.0.0.1:PORT`/`localhost:PORT` 否则 403;Origin 存在且非本机则拒绝;叠加一次性令牌彻底关掉网页面。
- **S4**: `POST /translate` 把 `provider.apiKey` 明文 JSON 发到无特权端口 11017。桥接常未运行(正是端口空闲最易被抢占之时),同机他用户/恶意进程可抢先绑定该端口,插件会把密钥+整篇 PDF 交给它。`assertLocalServiceURL` 只保证「不出本机」,插件↔桥接这一跳无身份验证。修复: 与 2.0.10 对子进程的纪律一致 —— 让桥接从自身环境变量读密钥,不再经 socket 明文上传;或一次性令牌 header。S2/S3/S4 都在桥接内,一次令牌+Host 校验+basename 可合并覆盖。
- **S5**: knownSecrets 按插入序迭代;先注册短密钥再注册长密钥(用户先粘错/截断再存完整),`sk-live-abcd1234efgh5678ijkl` 被替换成 `[REDACTED]efgh5678ijkl` —— 后半段裸露。修复一行: 迭代前按长度降序 `[...knownSecrets].sort((a,b)=>b.length-a.length)`。

## 4. P3(低/纵深加固)

- **【S6, 已复现】非 Bearer 的 Authorization scheme 值不被兜住**: `Authorization: DeepL-Auth-Key <key>` 只吞掉 scheme 名,密钥本体存活(`[REDACTED] not-a-uuid…`)。自己的 key 有注册串兜底,漏的是响应体回显的变体头。修复: authorization 模式消费 scheme+值两段(`security/logSanitizer.ts:8`)。
- **keyCache 陈旧写回竞态**: getApiKey 的 findLogin 最长等 4s,期间用户改/删密钥(setApiKey 先 delete 缓存),先前那次 getApiKey 解析后无条件 `keyCache.set(旧密钥)` → 本会话后续请求继续用已轮换/删除的旧密钥。加失效代次计数,写缓存前比对(`security/credentialStore.ts:105`)。
- **凭据库锁定时删除密钥虚假成功**: `setApiKey(id,'')` 在 findLogin 抛错(凭据库锁定)时落 fallback 分支只删明文副本、`return 'removed'`,Login Manager 条目原样存活并随 profile 备份 —— 是 P2-7 的镜像。删除路径 removeLogin 失败应返回 'failed'(`credentialStore.ts:120-170`)。
- **`Zotero.PaperMirror.getApiKey` 暴露在公共 API,返回明文密钥**: 一行 `Zotero.PaperMirror.getApiKey('openai')` 取回全部服务商明文(含明文回退)—— 把「其他插件需枚举凭据库」降为一行调用,也便利「诱导用户在 Run JavaScript 粘贴一行」的社工。设置页实际只需 hasApiKey/set/delete。公共面缩为 `hasApiKey(id)`(`startup.ts:268`、`preferences.ts:761`)。
- **shutdown 清 sanitizer 密钥集但不清 keyCache**: 禁用插件后 keyCache 明文密钥仍驻留至 JS 上下文销毁。导出 `clearKeyCache()` 在 shutdown 与 clearSecrets 并列调用(`shutdown.ts:32`)。
- **持久缓存文件默认 umask(通常 0644),译文全文对同机他人可读**: 同版本(2.0.6)把**短命**导出 PDF 加固到 0600,却把**长期驻留**的译文缓存留默认权限 —— 译文即论文内容,生命周期更长防护反更弱。写后尽力 `setPermissions(0o600)`,目录尽力 0700(`cache/cacheManager.ts:108/203/105`)。
- **UI 直显与崩溃路径缺一道 sanitize 兜底**: translationPane.ts:1356、readerSession.ts:887/1541/1694/2136、preferences.ts:898/926 的 error.message 上屏(全 textContent,无 innerHTML 风险)当前靠「上游全干净」约定成立;裸通道是 errors.ts:80(mapFetchFailure 透传任意 e.message)与「Invalid endpoint URL: ${url}」。建议在 PaperMirrorError 构造或 UI sink 统一过一次 sanitize，消灭单点约定。
- **400 错误片段可回显论文原文**: errors.ts:42/45/62 把响应体前 200 字拼进 message,回显请求体的病态网关会把页面原文带进 UI 错误行与 lastErrors 环形缓冲(≤200 字、仅错误路径)。建议片段仅当以 `{`/`[` 开头(错误 JSON 形状)才拼入。
- **registerSecret 最小长度 4 过短**: 注册 `test` 会把含 "test" 的所有日志打成碎片(诊断自毁,非泄露)。下限提到 8(`logSanitizer.ts:27`)。
- **桥接请求体无大小上限**: 按客户端声明的 Content-Length 一次性读入内存(`babeldoc_server.py:194`),恶意方可 DoS。设上限(如 200MB)超限 413。
- **卸载不清任何持久痕迹**: `bootstrap.js:78` uninstall 空实现 —— prefs(含用户术语表/提示词/万一存在的 apiKeyFallback 明文)、Login Manager 条目、缓存目录全残留。Zotero 标准行为,但建议 uninstall 尽力清 apiKeyFallback+移除凭据条目+clearAll,或在 PRIVACY.md 列出卸载后需手动清的三处。
- **verify-xpi 禁止清单只防 mac 残骸**: 打包安全主要靠 build.mjs 正向白名单(tests/docs/dist 结构上进不去,已实测确认);缝隙是误落入 locale/assets 的非 mac 文件(`.env`/`.key`)会被原样打包。verify-xpi 增补对 `.env`/`*.key`/`*.pem`/源码扩展名报错(`scripts/verify-xpi.mjs:18`)。

## 5. 已验证成立的不变量 / 干净路径(核查方法)

- **密钥只进请求头,绝不进 URL/body/query**: 逐 provider 核对 —— openaiCompatible `Authorization: Bearer`、anthropic `x-api-key`、gemini `x-goog-api-key`、deepl `DeepL-Auth-Key`;apiPath 只拼路径不拼 key。唯一 URL 承载凭据的是 Bing 免费引擎的**会话 token**(非用户密钥,在 Bearer 头)。
- **密钥不进缓存/持久化/序列化/剪贴板/postMessage**: 全部 `JSON.stringify` 站点逐一核对;settingsIdentityHash/cacheKey/segmentContext 逐字段确认**不含 apiKey**;providerProfiles 序列化字段白名单不含密钥;testConnection overrides 不接受 apiKey、ValidationResult 只回错误码;2.0.10 新增 producedBy 仅 provider id。全仓无 postMessage。
- **HTTP 层不记请求体/头**: httpClient 两条路径与 pdfService requestJSON 均 `logBodyLength:0`;错误对象不携带 headers。
- **模型输出只经 textContent 渲染**: 全仓 innerHTML/outerHTML/insertAdjacentHTML/document.write/createContextualFragment/eval/new Function 代码命中 **0**(唯一 DOMParser 解析构建期 inline 的品牌 SVG 常量并校验 nodeName)。恶意翻译响应无脚本执行面,不被跟随发额外请求。
- **无遥测**: 无 telemetry/analytics/sentry/beacon;modelCatalog 的文档 URL 是展示常量,运行时不 fetch。
- **出站主机仅用户所选服务商**: 逐路径核对,用户选 A 时无任何路径把文本/密钥发向 A 之外(bing-free 的多端点/轮换/Edge 兜底均限微软或用户自有主机);2.0.1 的「自定义 Base 时禁用 Edge 兜底不静默出网」未回归,2.0.10 无 scheme fail-closed 到位。
- **传输安全强制**: checkEndpointURL 强制 HTTPS(http 仅 localhost 或显式门闸),所有请求入口均经过;唯一直连 Zotero.HTTP 的 pdfService 经 assertLocalServiceURL 强制 loopback、无 override;TLS 失败→status 0→NETWORK,无静默降级。
- **桥接 /result 的 task_id = uuid4().hex(122 位熵)**: 读取面有效防护,他人无法猜测读取受害者任务结果;缺陷在提交/写面(S2/S3)不在读面。
- **sanitizer 生命周期/性能**: 换密钥后旧密钥留在集合是**好事**(in-flight 请求/晚到的网关回显仍被兜住,高熵串零误伤);无 ReDoS;registerSecret 精确替换用 split/join 无正则转义问题。
- **剪贴板出口**: 5 个 copyString 调用点逐一核 —— copyDiagnostics 仅脱敏计数与错误码枚举、geometryAudits detail 仅合成 id+几何无文本;copyLayoutCorpus 含原文但按钮名+payload note+toast 三重自我声明(设计内授权);术语/讲解为用户显式动作。无未声明的敏感写入。
- **会话销毁**: lastPartial 显式置空(释放 ~26MB canvas);lastExplanation 随 session 从 toolbar Map 解引用而不可达。

## 6. 建议修复顺序

1. **第一批(封泄露 + 桥接链)**: S1 补四条 sanitizer 模式 + profile 解析注册(半小时,直接封死 diagnose/UI/网关回显三条链);S2+S3+S4 桥接令牌 + Host 校验 + filename basename + 体积上限(都在 `babeldoc_server.py` 内,一并做);S5 长度降序(一行)。
2. **第二批(密钥卫生)**: S6 authorization 模式;keyCache 失效代次;凭据库锁定删除返回 failed;getApiKey 移出公共 API;shutdown 清 keyCache。
3. **第三批(纵深)**: 缓存文件 0600;UI/构造器统一 sanitize 兜底;400 片段 JSON 形状门;uninstall 清痕迹或文档化;verify-xpi 机密扩展名报错;registerSecret 下限提到 8。

## 7. 说明

S2/S3/S4 只在 `pdfExportMode = 'service'`(高级模式,用户显式安装并运行本地桥接脚本)时可达 —— 默认的 builtin 导出与在线翻译路径不触及桥接。但一旦启用,S2+S3 构成从恶意网页到本地代码执行的完整链,应作为第一批处理。S1 影响面更广(任何配了 `?key=` 端点的用户,一贴诊断即泄密),同为第一批。
