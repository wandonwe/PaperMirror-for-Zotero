## 总评

## P1(建议尽快修,可合为 1.0.2)

### P1-1 裸占位符前缀碰撞:PM1 会吃掉 PM10 —— 公式/引用可能被悄悄弄丢

`src/reader/formulaGuard.ts` `restoreFormulas()` 与 `verifyPlaceholders()`:
模型丢括号时的裸形式回退用 `text.includes('PM1')` / `split('PM1').join(...)`,
而 "PM1" 是 "PM10"…"PM19" 的前缀:

- `verifyPlaceholders`:译文里只有 PM10 时,PM1 被误判"存在"→ 丢 token 的译文
  被接受,进入还原;
- `restoreFormulas`:对 PM1 的裸替换会把 "PM10" 撕成 "原文1" + "0",既毁公式又
  留下垃圾字符。

0.9.24 起引用/统计量也进占位符,单块 >10 个 token 已是常态,此 bug 从理论隐患
变成现实概率。**修法**:裸匹配改用带边界的正则 `new RegExp('PM' + n + '(?!\\d)')`,
两处同改;还原顺序改为 token 序号降序(先长后短)可双保险。

### P1-2 keep-origin 段一旦进页缓存,普通刷新永远救不回来,且诊断失明

`translationManager.ts` 止损链路:段落连败两轮 → `failedSegments` ≥2 → 后续运行
排除出 `toTranslate`(keepOrigin='repeated-failure')→ `untranslatedCount` 只统计
`toTranslate` → 计 0 → **整页写入页缓存**。后果链:

1. 该段永远英文,而"普通刷新"(bypass 页缓存但不清 `failedSegments`)重跑时该段
   仍被止损跳过——用户能用的只有全文档级的强制重译,与"刷新本页应该救活本页"的
   直觉相悖;
2. 后续访问命中页缓存的路径**不重建 keepOrigin**(cache-hit 分支只填 translations)
   → "诊断"导出显示该段 `untranslated` 而无原因,右键重译虽可用但用户无从知道
   该这么做。

**修法**:(a) 页缓存写入条件改为 `untranslatedCount === 0 && keepOrigin.size === 0`,
或缓存时携带 keepOrigin 元数据;(b) `retranslatePage('normal')` 清除本页 blocks
对应 hash 的 `failedSegments` 条目(普通刷新即给一次新机会,与用户预期一致)。

## P2(下个小版本窗口内处理)

1. **提取信号量并发上限有竞态缺口**(`withExtractionSlot`):`if (active>=2) await`
   与 `active++` 不是原子的——等待者被唤醒但尚未自增时,新调用看到 active=1 直接
   通过,短暂出现 3 路并发提取。上限是软性能约束,不致错,但改为
   `while (active >= 2) await` 循环复查即闭合。
2. **单段重译会被翻页静默取消且报错文案失真**:`page-N-seg-id` 任务键不在
   `setCurrentPage` 的 `cancelExcept` 保留集内,右键后一滚动就被取消;catch 里
   CANCELLED 与真失败同路,胶囊提示"响应无效或被拒"。修:保留集加入 seg 键
   (或按前缀保留),CANCELLED 单独文案/不提示。
3. **右键"重译此段"只存在于左右对照**,覆盖模式没有等价入口——同一能力两种模式
   一有一无,建议 overlay 的段落 hover 菜单补齐。
4. **flashNotice/setTask 无销毁保护**:右键重译的 Promise 回调在会话销毁后仍会
   `setTask('flash', …)`;当前 setTask 内部未见 `destroyed` 短路(startPolling 有)。
   加一行守卫即可,避免关闭标签页瞬间的僵尸通知。
5. **error / no-text-layer 页每次路过都全量重试提取**:ensurePage 的提前返回名单
   不含这两态(设计上允许重试),但没有退避——扫描件文档里来回滚动会反复支付
   提取成本。建议:失败页记一个短 TTL(如 30s)内不重试。
6. **prefetch 提取无"当前页完成"门槛**:0.9.22 后邻页提取即刻开跑(注释里
   "No done-guard" 是针对进 lane 的请求说的,提取已移出 lane,该前提失效)。
   1.0.1 的超时兜住了死锁,但未渲染页仍会白占 20s 槽位。建议:仅当前页进入
   translating 后再放邻页提取,或提取槽给当前页绝对抢占。
7. **验收路径重复计算 stripProtectable**:每块 accept 至少跑 2 次全量正则
   (looksTranslated 源+译),残留检测再跑一次;40 块页面约百余次。建议按块
   memoize(WeakMap 或在 protectedBlocks 里带上 stripped 缓存)。
8. **fitFontSize 每块每次渲染读一次 getPref**(覆盖模式字号倍率):Zotero prefs
   服务调用不算免费,一次渲染 50 块 ×每次重排。建议每次渲染 pass 读一次传入。

## 结构性债务(不改行为,择机做)

- `translationManager.ts` 已 1668 行,`translatePage` 一个函数串起缓存/分块/并发池/
  三级补救/残留补译/纯文本兜底/止损记账,认知负担大。建议拆出
  `repairChain.ts`(补救+兜底+止损)与 `pageDiagnostics.ts`(记账),manager 只留
  编排;现有依赖注入形态支持无痛拆分。
- `readerSession.ts` 1895 行,身兼会话生命周期、双视图渲染调度、任务胶囊、菜单、
  剪贴板、笔记导出。建议先拆 `pageFlowController`(轮询/页变更/预取联动)。
- `looksTranslated` 的规则已经是"比例 + 截断 + copy-dominance + 混合残留 + 两豁免"
  的复合体,散在 manager 里;建议整体下沉到 residueRules.ts 暴露单一
  `classifyTranslation()`,manager 只消费结论——也方便未来按 retain-pdf 的
  warning/error 分级扩展。

## 测试盲区

- 纯逻辑层覆盖极好(530 例);盲区集中在 DOM 侧:overlayFit 的字号倍率分支、
  translatedPageView 的 role_min+倍率与 flow/overlap 联动、readerSession 的
  轮询-预取-胶囊状态机,均无自动化(Zotero 环境限制,可用 jsdom 近似覆盖前两者)。
- 提取路径的回归全部基于合成几何;建议沉淀 3–5 个真实论文页的脱敏 fixture
  (rects JSON 即可,不含版权文本),把 RSNA 页/三栏页这类历史战场固化成数据回归。
- provider 适配器的 plain 模式仅经由 mock 间接覆盖,三家适配器的
  `request.plain` 分支(尤其 gemini 的 responseMimeType 切换)缺直测。

## 隐私与安全复查(通过)

- 密钥:未发现任何新增日志/诊断/错误路径携带 key 或 Authorization;诊断导出仅
  id/type/字符数/状态/计数,已有测试断言不含正文与译文。
- 不译词与术语表仅进 prompt 与占位符,不落盘到日志;缓存键为内容哈希。
- 网络面未变:仅用户配置的 provider;Retry-After 解析对异常头做了 try/catch。

## 性能观感

调度层(三分道 + 提取信号量 + 自适应 lane)结构合理;当前最大的隐性成本是
P2-7/8 的重复正则与 prefs 读取,以及 P2-6 的无门槛预取提取——都属"低垂果实"。

## 建议整改顺序

1. **1.0.2**:P1-1 + P1-2(外加 P2-1/2/4 三个一行级小修顺手带上)
2. **1.0.3**:P2-5/6(提取退避与预取门槛)+ P2-7/8(性能小修)
3. 之后:P2-3(overlay 单段重译)、结构拆分、fixture 化测试

无 P0;当前版本可放心继续对外发布,上述 P1 不影响主流程,但会在真实长文档
使用中以"公式变乱码/一段永远是英文"的形态偶发暴露,建议尽快落地 1.0.2。
