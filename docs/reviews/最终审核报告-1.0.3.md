## 质量轨迹

从 0.9.2 到 1.0.3,翻译内核与版面识别实质上重写了一遍:

- **正确性**:占位符保护(公式/引用/统计量)+ 清单校验;RetainPDF 源码级判定
  规则(copy-dominance、截断、混合残留、数据密集/署名豁免);三级补救 + 纯文本
  兜底 + keep-origin 止损;表格逐格翻译。
- **性能**:提取移出并发槽(信号量 + 超时 + 僵尸治理 + 文字层恢复链);三分道
  调度 + 公式风险评分;429 按 Retry-After 退避驱动自适应限流;段落级缓存。
- **版面**:栏检测反焊接(覆盖投票)、规范阅读序、区域合并列标注权威、
  出版商样板剔除、图框硬屏障、页面基准字号。
- **可观测**:页级诊断、段级状态、右键单段重译、一键脱敏诊断导出。
- **工程**:测试 107 → **538** 项;可复现构建;发布闸门;MIT 致谢合规落地。

本轮教训值得记录:三次现场回归(每页点圆环、表格卡死、到页假完成)全部源于
**新路径脱离了旧路径的保护性约束**(提取脱离看门狗、preserve 块脱离像素框映射、
空文字层脱离"空≠完成"的判断)。已针对性加了兜底(渲染异常降级、错误态可重试、
重试环),但这个模式提示:今后任何"把 X 移出 Y"的重构,清单式核对 Y 曾附带的
每一条保护。

## 审核发现最终状态

已修复(本轮全部闭环,均有回归测试):表格单元格页面栏号(1.0.2)、PM1/PM10
裸占位符前缀碰撞(1.0.2)、keep-origin 页缓存冻结 + 普通刷新止损清理(1.0.2)、
role_min/字号倍率移植到实际渲染路径(1.0.2)、提取信号量 while 竞态(1.0.2)、
单段重译滚动保活(1.0.2)、strict 表格 pxOf 崩溃 + 渲染兜底(1.0.3)、文字层
空结果假完成 + 重试环(1.0.3)、提取悬挂死锁(1.0.1)、切页隔离与僵尸去重
(1.0.2, Codex)。

仍开放(全部 P2,按建议顺序):

1. **死代码清理**:`translatedPageView.ts` 的 `buildTranslatedPage` /
   `settleTranslatedPage` / `buildFallbackPage` 约 700 行零消费者(被 strict
   渲染器取代的旧重排路径)。留着的代价已经付过一次——0.9.28 的字号功能就落
   在了这条死路上。建议 1.0.4 删除(git 历史可找回),只保留在用的帮助函数。
2. **失败页无退避**:error / no-text-layer 页每次滚过都全量重试提取;扫描件
   文档来回滚动会反复支付成本。建议 30s 级 TTL。
3. **性能微修**:验收路径 stripProtectable 每块重复计算 2–3 次(可按块
   memoize);覆盖模式 fitFontSize 每块读一次 getPref(每渲染 pass 读一次即可)。
4. **覆盖模式缺右键重译**:与左右对照能力不对齐。
5. **测试盲区**(接受为已知约束,但列入路线):strict/overlay 的 DOM 路径无
   自动化(可用 jsdom 覆盖核心);真实页面几何 fixture(把 RSNA 页、三栏页、
   Table 4 页的 rects 脱敏固化为数据回归);三家 LLM 适配器 plain 模式直测。
6. **结构拆分**(1.1 窗口):translationManager 1803 行 / readerSession 1913 行,
   建议拆 repairChain / pageDiagnostics / pageFlowController;looksTranslated
   规则族下沉 residueRules 统一为 classifyTranslation()。
