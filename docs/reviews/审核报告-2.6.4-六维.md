## 2. 发现清单(按严重度、再按影响面)

严重度:P0 数据/隐私/崩溃;P1 整页可读性;P2 局部质量;P3 效率/整洁。

### D-1 · P1 · 排版放弃率 6–7%,其中含整段正文
- **证据**:radiology `placement.abandoned` = 14/208;fletcher = 7/114。`placementProbe` 逐块:fletcher p8 `page-7-region-10` list **1051 字符、246×176px 放弃**(即用户截图里右栏整段英文残留);p11 `region-4::p0/p1` 352×52 / 352×183 放弃;p5 `region-6::p0` 422×129 放弃。radiology p2 侧栏 4 个小标题(51–101px 宽)全部放弃;p1 主标题 543×32 放弃(annex 救回另一半)。
- **根因(分两类,后者为假设)**:
  1. 正文(paragraph/list)按设计不单块缩字(`allowsFontShrink`,strictPageReplacement.ts:109),只能靠扩边;扩边又被"未建模墨迹"闸否决(`inkBlocked` 64 / 19,radiology p11 一页 38 次)→ 扩不出、缩不得 → 放弃。
  2. 【假设】小标题译文比英文盒宽(中文标题 3–4 字 × 13pt 已超 51px),缩字梯只有 0.94/0.88 两档且标题无 charBudget 压缩重试;需 `abandonReason` 证实。
- **修法**:① 探针加 `abandonReason`(width / height / ink / shrink-floor / compress-exhausted),先把因果做实;② 标题类允许第三档 0.82;③ 对"扩边被墨迹否决"的正文,增加**页级统一缩字**末位救援(同页所有正文块一起缩 0.94,不发花)再放弃。
- **验证**:同一诊断导出 `abandoned` 计数下降;`abandonReason` 分布;新增 layoutSafety/strict 单测锁定统一缩字只在 ink-blocked 场景触发。

### EF-1 · P3(高影响)· 表格页请求碎片化,系统提示占比失控
- **证据**:`planChunks`(segmenter.ts:238–297)在表格格与正文之间**无条件断批**(硬边界),而阅读序里格与正文交替出现,断开后同类批次不再合并。chen2023-p5:**9 次请求 / 1570 字符正文**(平均 174 字符/请求,每次另付 1,389 字符系统提示,非正文开销 79.9%);wu2026-p6:9 次 / 1600 字符(74.7%);radiology2023-p3 / p11:4 次,开销 53% / 54%;nejm-defuse3-p7:6 次(48%)。全语料 78 次请求中,表格页贡献 40 次。
- **根因**:硬边界 + 单趟顺序打包;`MAX_BLOCKS_PER_REQUEST = 24` 又让格密集页(chen-p5 有 177 格)天然多批。
- **修法**:两趟打包 —— 正文流与格流各自按预算独立打包(块内顺序不变;id 驱动映射,批次顺序无关正确性),再合并输出;格批的块数上限单独放宽(格通常 < 30 字符)。
- **预期**:chen-p5 9→2–3,wu-p6 9→2–3,radiology p3/p11 4→2;全语料 78→约 50 次;表格页输入 token 降 40–60%。
- **验证**:`pipeline-baseline.json` 的 chunks/fastChunks 有意变化(逐页 diff 进 CHANGELOG);新增 planChunks 单测:交替 [正文,格,正文,格] 输入 → 恰 2 批。

### C-1 · P2 · 数值表的表头行逃出网格,成为孤立单词块
- **证据**(离线结构统计,单行 < 90 字符的散文块):radiology2023-p3 11 个("Detector"、"Scan"、"FDA"、"Collimation"、"Thresholds"…,Table 3 的多行堆叠列头);chen2023-p4 6 个("Characteristic"、"Development Set (n = 225)"…);chen2023-p5 5 个("Patients with"、"Vulnerable"…);wu2026-p6 8 个("SNR"、"CNR"、"difference"…)。
- **根因**:`detectTableRegions` 的扫掠只收"区域内"与"区域**侧边**行对齐"的块(tableGuard.ts 扫掠规则 a/b/c);表头在区域**上方**、无数字、与数据行不同高 → 三条都不沾。
- **后果**:每个列头被当作独立段落无语境翻译("Vulnerable"→?),并把正文批次切碎(叠加 EF-1)。
- **修法**:向上扫掠 —— 区域顶边上方 ≤ 2.5em 内、x 中心落在某列带内、≤ 6 词的短块并入区域,作为 row 0 表头(`buildTableModel` 已把 row 0 有词格判为 text 翻译)。
- **验证**:上述 4 页快照有意更新(列头进入 `tableRow: 0`);其余 30 页逐字节不变;突变(去掉向上扫掠)→ 快照红。

### C-2 · P2 · 字间空格的 "R E F E R E N C E S" 不被识别为参考文献标题
- **证据**:jacc2020-p15 出现单行块 "R E F E R E N C E S" 与词级碎块 "angiography" / "compared" / "to"(三栏参考文献被当正文切碎并翻译)。这是 2.5.10 时记录的遗留项,本次统计再次命中。
- **修法**:`REFERENCES_HEADINGS` 允许字母间空白(`R\s*E\s*F\s*E\s*R\s*E\s*N\s*C\s*E\s*S`);references 区按用户设置保留。
- **验证**:jacc2020-p15 快照有意更新;单测锁定正则。

### B-1 · P2 · 诊断口径:排版阶段放弃的块仍报 `translated`
- **证据**:`exportDiagnostics`(translationManager.ts:986)按"有译文即 translated"计;放弃只出现在 `placement.abandoned` 与 `placementProbe[].state`。两篇诊断 `blocks[].state` 全为 translated/preserved,而实际 21 块从未显示译文。审核 fletcher p8 时正因此误判为"无失败块"。
- **修法**:块级 state 联表排版结果(`unplaced`),并带 `abandonReason`(见 D-1)。`baseline-report.mjs` 的 placeRate 已正确,块表要与之对齐。
- **验证**:`diagnosticsPrivacy.test.ts` 扩展:probe/state 不含任何文本;新增 state 联表单测。

### F-2 · P3 · 生产环境无法度量 token:未采集 API usage,未启用服务商提示缓存
- **证据**:`providers/anthropic.ts`、`openaiCompatible.ts`、`geminiNative.ts` 均不读取响应的 `usage`/`prompt_tokens`/`input_tokens`;诊断 `usage` 只有缓存计数。Anthropic 通道未设置 `cache_control`;系统提示约 350 token,低于 OpenAI 自动前缀缓存的 1024 token 门槛 —— 现状下两家都拿不到缓存折扣。
- **修法**:① 响应 usage 计数进诊断(纯数字);② Anthropic 系统块加 `cache_control: ephemeral`(术语表/自定义提示放在可缓存前缀之后);③ OpenAI 侧唯一杠杆是 EF-1(合并批次)。
- **验证**:诊断出现 `inputTokens/outputTokens/cachedInputTokens`;同一文档重译时 cached 比例 > 0。

### F-3 · P3 · 载荷结构性开销 30.9%
- **证据**:id 9.0k(平均 17 字符/块,"page-3-region-12")、previousContext 13.2k(续批固定 300 字符)、JSON 键名/`type`/`charBudget` 32.4k。
- **修法(收益有限,排后)**:请求内用短 id(`b0…bN`,本地映射回真实 id)省 ~5%;`type` 字段若提示词不消费可去;上下文 300→200 边际。
- **不建议现在做**:短 id 会削弱日志/诊断可读性,收益远小于 EF-1。

### A-1 · P3 · 几何检测重复调用
- **证据**:每页 `detectGuttersBanded` ×3、`detectGutters` ×3–4、`detectColumns` ×4(spanBlockBuilder.ts:699 与 :816 输入完全相同)、`groupIntoRows` ×2。bench 总耗时 194 ms/34 页,最大 14 ms/页 —— **无用户可感知代价**。
- **修法**:一次算完在 `buildBlocksFromSpans` 内传递;仅为整洁,必须证明 34 快照逐字节不变。
- **优先级**:最低。

### A-2 · P3 · DOM 侧强制回流
- **证据(静态)**:`ladderFits` 每步写样式后读 `scrollHeight/scrollWidth`(强制布局);`pmShrinkFit` 对每块最多 3 次扩展 × 梯子 + 2 档缩字 × 梯子;`pmGeometryAudit` ≤ 4 轮 × O(n²) 对审。radiology p3 有 77 个可替换块。真实诊断页均 5.9 s 主要是 API 等待,排版耗时未单独计。
- **修法**:先加 `layoutMs` 计时进诊断;若单页 > 50 ms 再做读写分离(先批量写样式、再批量读)。
- **优先级**:测量先于优化。

### C-3 · P3 · 夹具覆盖缺口
- 已覆盖:双栏正文、三栏参考文献(jacc)、三栏正文(hakime)、Springer/Radiology 侧栏封面、数值表、文本定义表、L 形图注、单沟满幅页。
- **未覆盖**:横版页、公式密集页、脚注密集页(每页 5+ 条脚注)、参考文献续页(整页三栏)、图侧/图上图注、多图分图注(A/B/C 各自一段)、单栏预印本(arXiv)、竖排/旋转文字。
- **建议**:每类做一个最小合成夹具(与 `tests/unit/paragraphHeuristics.test.ts` 里的合成行同法),真实语料到手后替换。

## 5. 看到但建议不动

- **A-1 几何重复调用**:收益不可感知,改动触及 2.6.x 所有触发路径,风险/收益比差;等下次必须改 `buildBlocksFromSpans` 时顺手做。
- **F-3 短 id / 去 type / 上下文 200**:合计 < 8% 输入,且损失可调试性;EF-1 做完再评估。
- **`globalMissed` ±20pt、近邻 24pt、宽度门 40%、`minSpan` 0.2 页高**:均有实证下界(chen-p10 9pt、fletcher-p7 骑界两行)与上界(hakime 邻沟 53pt);缺的是中间区间的反例页,不宜盲调。
- **hakime 形态的分带假沟 + 全局盲**:会误建三栏 regime,但需要"全局投票全盲"与"栏内空白带"同时出现,尚无实证页。
