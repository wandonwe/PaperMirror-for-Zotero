# PaperMirror 文镜 · 功能审核报告（v2.1.6）

目标四维：**① 性能优化 · ② API 节省 · ③ 排版优化 · ④ 工作流程优化**。方法：四个只读子代理各审一维，给出 `文件:行` 级实证发现，本报告去重、交叉引用并排出批次。所有发现均为静态分析，未改动代码。

约束前提（延续项目硬承诺）：BYOK，不记录密钥/原文/译文；模型输出仅经 textContent 渲染；缓存 schema v5；不重新引入 2.1.6 已删除的 babeldoc「服务模式」桥接。

## 一、P0 精选（低成本、高影响，建议第一批）

| # | 维度 | 标题 | 文件:行 | 工作量 |
|---|---|---|---|---|
| P0-1 | 排版·正确性 | **导出 PDF 对放不下的块「先涂白原文再截断」→ 成品静默丢正文** | `src/pdfgen/translatedPdfBuilder.ts:147-189`、`textWrap.ts:99-110` | S |
| P0-2 | 性能 | 三处高频取样 canvas 缺 `willReadFrequently`，getImageData 走 GPU 回读 | `strictPageReplacement.ts:287,519`、`zoteroReaderAdapter.ts:807` | S |
| P0-3 | 性能 | 诊断探针 `pmProbe` 无条件落在每页 settle 热路径（逐块逐行 getImageData） | `readerSession.ts:1497-1505`、`strictPageReplacement.ts:951-993` | S |
| P0-4 | API | `maxOutputTokens` 进入 settingsHash → 提高输出上限即整篇作废重译 | `readerSession.ts:810-819`、`cacheSchema.ts:58-60,173-174` | S |
| P0-5 | 工作流 | 导出译文 PDF / 清本文缓存 / 诊断 三个动作**零界面入口**，只能敲控制台 | `startup.ts:191-198`、`translationPane.ts:686-700` | S |

P0-1 是唯一的**正确性**级别问题：导出路径与阅读器「放不下就露原文」的核心契约相反，长译文段在交付的 PDF 里被白块盖住原文、译文截半加省略号，读者永久看不到且无提示。其余四条都是 S 工作量的高杠杆项（两条纯提速、一条省整篇重译、一条把旗舰功能从「隐藏」变「可点」）。

## 三、② API 节省

| # | 标题 | 文件:行 | 影响 | 工作量 | 优先级 |

## 六、建议分批

**第一批（P0，全 S 工作量，混合四维，回报最高）**
- LO-1 / P0-1：导出 PDF 放不下的块保留原文，不再涂白截断（正确性）
- PF-1：三处 canvas 加 `willReadFrequently`
- PF-2：`pmProbe` 下热路径（默认关，仅按需/诊断开关时对当前页跑一次）
- API-1：`maxOutputTokens` 移出 settingsHash
- WF-1 + WF-2：译文面板加「更多」菜单 → 导出译文PDF / 清本文缓存 / 诊断（复用现成 ftl 串）

**第二批（P1，中等，质量与省钱主力）**
- LO-2：结构化摘要拆段改「尽力对齐」；LO-3：缩字按页决策，正文不单独缩
- API-2：同页相同内容去重；API-4：精简 system prompt
- WF-3：首次引导 + WF-5：隐藏首选项补进设置页（timeoutMs/useContext/overlayFitMode）；WF-6：单段重译加提示
- PF-3：段落库分片；PF-4：底图位图 LRU

**第三批（P2/P3，深度与打磨）**
- 「导出 PDF 版式」合集：LO-4 CJK 禁则 + LO-5 标题可译 + LO-6 扩边阶梯 + LO-8 表格逐 member 兜底
- API-3 跨文档共享段落库；API-5 autoPrefetch 收窄+去抖；API-7 上下文收窄；API-8 讲解缓存
- PF-5~PF-10 各项微优化；WF-7~WF-10 打磨
