# 导出方案:独立的「诊断文件」与「翻译语料」入口

> 状态:**方案,未实现**。本文只整理设计与取舍,不含代码改动。
> 依据:用户 2026-09-08 的需求 + 定稿意见,对照 2.8.4 实现逐项核对。
> 定稿:spans 重解析且诚实标注;轻量诊断留存;端点主机名默认脱敏;语料入口独立于调试开关。

---

## 0. 结论先行

方案可行。有一处**硬事实**决定了语料包的诚实边界:

> **spans 没有被留存。** `layoutCorpus()` 取的是 `adapter.getTextLayerItems()` —— 只有
> 阅读器**渲染过的页**才有文本层,非当前页拿不到;而 `buildBlocksFromSpans` 消费完
> spans 之后只留结构块,原始 spans 当场丢弃。所以"导出所有已处理页的 spans"只能在
> 导出时**重新解析**,不可能拿出翻译当时的那一份。

已定:采用重解析 + `re-extracted` 标注 + 一致性检查,**不为导出长期保留全篇 spans**
(那会与 2.8.3 的内存淘汰正面对冲,spans 比结构块还大)。

另两条决定了工作量分配:

- **诊断包不再有"缺失页"**:轻量诊断快照(第 2 节)补上了淘汰页丢掉的逐块明细,
  其余(页状态、页级指标、placement / geometryAudits / abandonedBlocks / probe)本来
  就不随淘汰丢失。→ 先做诊断包,风险最低。
- **不打包,一次导出就是一个纯文本文件**(用户 2026-09-08 定;此前的 ZIP 方案作废)。
  格式见第 6 节:JSONL —— 一行一个 JSON 对象,首行是 manifest,其后每页一行。
  它同时消掉了 `@mozilla.org/zipwriter;1` 的可用性风险与自写 store-only ZIP 的
  八十行 CRC32 代码,而"逐页读、逐行追加写"这条流式路径原样保留。

## 1. spans 的一致性检查:能证明什么、不能证明什么

### 1.1 检查必须走**与翻译相同的结构处理流水线**

只跑 `buildBlocksFromSpans` 不算数。真实抽取路径是(`textExtractor`):

```
getPageData(chars) ──► buildBlocks(chars, opts)
                        └─ opts: pageWidth/Height、bodyFontSize、includeReferences、
                                 referencesAlreadyStarted、imageRectsPdf
      ──► orderBlocksForReading
      ──► structureTableCells(…, em, noTranslate)
      ──► coalesceRegions(散文块)
      ──► orderBlocksForReading(合并后重排)
```

检查必须完整重放这条链,并**喂同样的 opts**,否则比出来的差异是自己制造的。

### 1.2 为什么"匹配"也只能说明重建结构一致

抽取的输入里有四项是**跨页累积或会中途改变**的:

| 输入 | 性质 | 后果 |
|---|---|---|
| `bodyFontSize` | 文档级正文字号的**滚动估计**,随读过的页不断修正 | 第 5 页当初用的值,和会话末尾重解析时用的值可能不同 |
| `referencesAlreadyStarted` | `referencesStartedByPage` **跨页累积** | 单页孤立重解析时,前文状态未必与当初一致 |
| `includeReferences` / `noTranslate` | 用户首选项,**可中途改** | 改过就必然不同 |
| 抽取路径(char 流 / 文本层 / 字符兜底) | 运行时择路,含 `(cid:` 未解码比例的启发式 | 重解析可能走上**另一条路径** |

所以结论必须写死在文件里:**`matched` 只说明"用同样的流水线重建出了同样的结构",
不等于"这就是当时那份 spans"。** 页文件里 spans 一栏永远是 `re-extracted`,不因为
匹配就升格。

> 附带一个小缺口:**当初走的是哪条抽取路径,现在没有记录。** 建议顺带在页状态里记
> 一个 `extractPath` 枚举(1 个字段,极小),否则重解析走了另一条路时连"路径不同"
> 这个最可能的原因都说不出来。这一条列为可选前置项。

### 1.3 三态判定

`structureMatch: "matched" | "mismatched" | "unverifiable"`

- `matched` —— 有可靠对照(留存的结构块还在),且逐项比对全等;
- `mismatched` —— 有可靠对照,但比对不等;附 `mismatchKinds`(见下)与计数;
- `unverifiable` —— **原始结构已被淘汰、或从未留存、或对照本身不可信**(例如上表四项
  输入中任何一项已知变化)。这时**必须是 `unverifiable`,不许写 `matched`**。

### 1.4 比对哪些字段(不止 id 与哈希)

逐块比对:`id` · `type` · `boundingBox`(带容差,单位 px,容差写进文件)·
`readingIndex`(阅读序)· `column` · `tableRow` / `tableCol` · `translationMode` ·
原文哈希。差异按类别计数:

```json
"structureMatch": "mismatched",
"mismatchKinds": { "count": 3, "type": 0, "box": 2, "readingOrder": 1,
                   "tableCell": 0, "translationMode": 0, "text": 0 }
```

### 1.5 不匹配时的硬规则

**不得按块 id 强行关联缓存译文。** 块 id 形如 `page-N-region-M`,是**按位置生成的**
—— 重建后的 `region-3` 可能根本不是当初那个 `region-3`,照 id 贴译文会产出一份
"看起来对齐、其实错位"的语料,比缺失更糟。

因此:`structureMatch !== "matched"` 时,该页的 `translations` 一栏记
`missing:structure-mismatch`,页文件里仍然给出重建的结构与 spans(它们本身是真实的),
但**不填译文**。`manifest` 单列计数。

## 2. 轻量诊断快照(替代"保留整个页面对象")

2.8.3 淘汰时把 `keepOrigin` / `rejectReasons` 一起清掉了;而且**光留这两个 Map 也不够**
—— 现有逐块诊断是遍历 `state.blocks` 现算的,`blocks` 一没,明细就没了依据。

所以留存的不是那两个 Map,而是一份**独立的、定长的逐块摘要**,在页完成时生成、
随轻量状态一起活着:

```json
{
  "runId": 137,                 // 产出这份摘要的运行序号
  "revision": 12,               // 译文修订号,便于与页状态对齐
  "blocks": [
    { "id": "page-11-region-4", "state": "unplaced",
      "keepOrigin": "unrecovered", "reject": "validator" }
  ]
}
```

- 只留:块 id、最终状态、`keepOrigin` 原因枚举、最后一次拒绝原因枚举;
- **不留**:原文、译文、异常原始消息;
- `runId` / `revision` 是**防混入**的关键 —— 重新翻译后 runId 变了,旧摘要立即作废
  (丢弃或标 `stale`),绝不把上一轮的逐块结论混进新一轮的诊断。

体量:约 60–80 字节/块,40 块/页 ≈ 3 KB/页;500 页 ≈ 1.5 MB。相对它换来的
"诊断包不再有缺失页",这笔账划算。

## 3. 数据来源盘点(逐字段核对过现有实现)

| 数据 | 现在存在哪 | 淘汰后还在吗 | 导出时的可得性 |
|---|---|---|---|
| **spans** | **不留存** | — | **只能重解析**,恒标 `re-extracted` |
| 结构块(id/类型/box/lineRects/column/tableRow·Col/translationMode) | `state.blocks` | ❌ | 重解析重建;可信度由 `structureMatch` 表达 |
| 译文 | `state.translations` | ❌ | 页缓存恢复(仅 `cached` 页);结构不匹配则**不填** |
| 逐块最终状态 / keepOrigin / reject | 现由 `state.blocks` 现算;两个 Map 淘汰时被清 | ✅ **改为轻量摘要后保留** | 直接可得 |
| 页状态 / 页级指标(requests、attempts、时序三段、token) | `state.diagnostics` | ✅ | 直接可得 |
| 排版结果 / 放弃原因 / 几何审计 | `readerSession` 的三个 Map | ✅ 不受淘汰影响 | 直接可得 |
| 排版探针(逐块像素盒) | `readerSession.placementProbe` | ✅ | **仅调试日志开启时采样**,否则 `not-sampled` |
| 会话级用量与计量 | manager / pane / cacheManager | ✅ | 直接可得 |

## 4. 导出范围与快照策略

### 范围
- 当前文档、本次会话中**所有已处理页**;已完成 / 部分完成 / 失败全部纳入。
- **未处理页只记状态,绝不为导出发起翻译。**
- 未处理页仍生成页文件(只含状态与 `availability`),让"少一个文件"永远不会被误读成
  "这页没问题"。

### 快照(逐页保护,不是全局暂停)
真正的整篇原子快照要么把全文装内存,要么锁住翻译,两条都违背约束。采用:

1. 导出开始记 `snapshotAt`,冻结**页清单与各页状态**(浅拷贝);
2. **逐页短时保护**:读某页前把它 `pin` 住,复制到临时容器后**立即释放**;
   —— 实现上复用 2.8.3 已有的 `inUse` 闸(`pagesToEvict` 把 pinned 页视为在用),
   不新增绕过淘汰的路径;
   —— **不在整个导出期间暂停淘汰**,否则长文档导出时内存会一路上涨;
3. 逐页读、逐页写,每页记 `readAt`;
4. `manifest.json` 写明 `snapshotPolicy: "page-at-a-time"` 与 `snapshotAt`,
   **不谎称原子**;
5. 导出期间新完成的页不回填已写出的部分,`summary.json` 记 `pagesStillTranslating`。

### 恢复
- 诊断包**不需要恢复**(第 2、3 节)。
- 语料包:重新抽取(PDF 解析,**无 API 调用**)+ 读页缓存。
- 恢复用**独立临时容器,不塞回 `manager.pages`** —— 否则污染 LRU 与页状态机,
  还可能把一页"复活"成热页。

## 5. 缺失与来源的表达(不能静默漏页)

每页一段 `availability`,各维度独立标注,取值固定四类:
`live` · `restored-from-cache` · `re-extracted` · `missing:<原因>`。

原因枚举:`evicted` · `cache-miss` · `never-processed` · `extract-failed` ·
`structure-mismatch` · `not-sampled`。

```json
{
  "page": 12,
  "availability": {
    "spans":        "re-extracted",
    "blocks":       "re-extracted",
    "translations": "restored-from-cache",
    "placement":    "live",
    "blockDigest":  "live",
    "probe":        "missing:not-sampled"
  },
  "structureMatch": "matched",
  "readAt": "2026-09-08T15:30:42.287+08:00"
}
```

`manifest.json` 汇总:`pagesTotal / processed / complete / partial / failed /
notProcessed / restored / reExtracted / missing`,外加
`structureMatch: { matched, mismatched, unverifiable }`。
**任何一页的任何一个维度缺失,都必须在这里数得出来。**

## 6. 文件、命名与格式

**不打包**。一次导出 = 一个纯文本文件,双击就能看、能 grep、能直接贴进 issue。

### 命名
```
PaperMirror_v2.8.5_diagnostics_20260908_153042_287+0800.jsonl
PaperMirror_v2.8.5_corpus_20260908_153042_287+0800.jsonl
```
- 版本**从运行中的插件取**:`startup(params)` 已有 `params.version`(`bootstrap.js` 传入),
  导出模块经模块级 `pluginVersion()` 读它 —— 不读常量、不硬编码。
- 时间:本地时区,日期 + 时分秒 + 毫秒 + `±HHMM`。
- 重名追加 `_2`、`_3`,**绝不覆盖**。
- **文件名不含论文标题。**
- 扩展名用 `.jsonl` 而不是 `.txt`: 它就是纯文本,但名字如实说明"一行一个 JSON",
  别人拿到不用猜。用户若更想要 `.txt`,改个后缀即可,内容一个字节都不用动。

### 格式: JSONL(一行一个 JSON 对象)
```
{"kind":"manifest", …}     ← 第 1 行: 版本、时间、范围、快照策略、完成/失败/缺失统计
{"kind":"summary",  …}     ← 第 2 行: 会话级汇总(usage / render / cacheWrites / engines / 放弃原因分布)
{"kind":"page","page":1, …}
{"kind":"page","page":2, …}
…
```
为什么是 JSONL 而不是一个大 JSON 数组:

- **可流式追加**。每页读完立刻 `IOUtils.write(…, {mode:'append'})` 追一行,
  整篇文档从头到尾不需要同时在内存里 —— 这正是原方案要 ZIP 流式写入的理由,
  换成纯文本一样成立,而且少一层格式。
- **写到一半崩掉,前面的行仍然可读**。大 JSON 数组缺个 `]` 就整份废掉。
- **机读零成本**。`baseline-report.mjs` 一类工具按行 `JSON.parse` 即可;
  现有从 RTF 解出多个顶层 JSON 连写的路子反而更麻烦。
- 人看也不难: 单行长,但编辑器软换行 + `python -m json.tool` 逐行看都行。

manifest 放**第一行**是有意的: 打开文件第一眼就是版本、范围与缺失统计,
不用滚到底。语料包的 `CONTAINS_SOURCE_TEXT: true` 同样在第一行(第 8 节)。

### 大小
语料包不压缩会比 ZIP 大几倍。23 页的真实长文档量级在几 MB,可接受;
真遇到几百页的文档再谈压缩 —— **在有人真的抱怨之前不做**,
这正是 2.8.4 "先量,再改" 的同一条纪律。

## 7. 交互流程

```
点击导出 →(语料才有)隐私确认 → 选择保存位置 → 进度 → 成功后「显示文件」
```

- 「更多」菜单两项:**导出诊断文件** / **导出翻译语料**;**不再复制到剪贴板**。
- **语料入口与调试日志解绑**:常驻「更多」菜单,不占主工具栏。调试日志只决定探针
  是否采样;未采样标 `not-sampled`,**不得因此阻止语料导出**。
- 菜单说明:
  > 导出当前文档已处理页面的数据,不会发起额外翻译请求。
- 语料确认文案(定稿):
  > 文件包含当前文档已处理页面的原文、译文和布局数据。分享前请确认你有权提供这些
  > 内容;不会导出 API 密钥。
- **保存对话框取消 = 直接结束**:不写任何文件,不回落到别的目录,只给一句"已取消"。
- **对话框不可用时**:弹一次询问"是否保存到 `<备用目录>`",用户同意才写。
  **绝不自动把含全文的语料写到别处。**
- 进度三段:准备(冻结清单)→ 写入(第 n / N 页)→ 完成。复用状态胶囊或 toast。
- **失败只报失败并指明阶段**(prepare / read-page / write-entry / finalize / save),
  失败后绝不提示成功。
- 「显示文件」:`Zotero.File.reveal(path)`(**需验证**);不可用则把路径写进 toast 与日志。

### 导出期间的硬边界
不调用任何翻译 API;不清缓存;不刷新翻译;不改任何页状态。有副作用的只有两件:
**逐页短时 pin**(`try/finally` 保证释放)与**写文件**。

## 8. 隐私

**诊断包**
- 沿用 `diagnosticsPrivacy` 的哨兵口径:原文 / 译文 / 密钥一个字都不进;
- 新增断言:**文件名不含文档标题**;
- **端点默认脱敏**(定稿):不再导出 `endpointHost`,改为

```json
{ "provider": "gemini", "endpointKind": "official", "customEndpoint": false }
```

  `endpointKind` 固定枚举:`official` · `custom` · `local` · `invalid` · `unknown`。
  **不导出域名、IP、端口、路径,也不导出主机名哈希。**
  分类只用现有设置即可算出:空或等于该服务商默认 baseURL → `official`;
  localhost / 127.0.0.1 / [::1] → `local`;URL 解析失败 → `invalid`;其余 → `custom`。

**语料包**
- 首行 manifest 的第一个字段 `CONTAINS_SOURCE_TEXT: true`,自我声明;
- 确认对话框 + 完成 toast 各提醒一次;
- 不含密钥、不含端点 URL。

## 9. 分期

| 期 | 内容 | 理由 |
|---|---|---|
| **P0** ✅ 2.8.5 | 轻量逐块摘要(第 2 节)+ `extractPath` 记录 | 它同时消掉诊断包的缺失页与"路径不同说不清"两个坑,且与导出解耦,可独立发版 |
| **P1** | 诊断包(全页范围、manifest/summary/page 三种行、命名、JSONL 流式追加写、端点脱敏) | 不碰 spans 难题,风险最低 |
| **P2** | 语料包(重解析 + 全流水线一致性检查 + 三态 + 从缓存恢复 + 不匹配不贴译文) | 复用 P1 的写文件骨架 |
| **P3** | 平台交互(FilePicker / reveal) | 两个 API 需真机验证,各有明确回落 |

每期照旧:单测 + 突变验证 + 结构闸;导出路径不碰提取 / 结构 / 排版,布局快照与请求
计划基线必须逐字节不变。
