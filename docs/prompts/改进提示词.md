# PaperMirror 改进提示词(给外部模型 / 编码代理)

> 用法:先贴 `项目简介提示词-给外部模型.md`,再贴本文;再附上你想聚焦的方向
> (可留空,让它自己从证据里找)。给有仓库访问权的编码代理时,把"执行规则"一节
> 原样保留 —— 那是防止它把项目改坏的护栏。

---

## 你的任务

对 PaperMirror 做一轮**以证据驱动的改进**:先从仓库自带的语料、基线和诊断里找出
当前最值得修的问题,再把它们做成可验证、可回滚的小批次。不要从"我觉得应该有"
出发,要从"数据里看到了什么"出发。

## 第一步:先量,再想(必须先做,结论要带数字)

按顺序跑并记录输出,任何建议都要能回指到这里的某个数字或某个夹具页:

1. `npm test` —— 931+ 用例全绿是起点;红的先修,不许绕。
2. `node scripts/baseline-report.mjs`(若有诊断 JSON 就喂进去)—— 看每页
   `unplaced`、`abandonReason` 分布、`requests/attempts`、token/页、`layoutMs`。
3. 对 `tests/fixtures/layout/*.snapshot.json` 做结构统计:每页块数、表格格数、
   `preserve` 占比、`column` 为 -1 或跨栏的块、单词孤块(≤2 词的 paragraph)。
   孤块和 -1 栏是"结构没恢复"的直接信号。
4. `tests/fixtures/baseline/pipeline-baseline.json`:请求数、payloadChars、
   dupBlocks 按页排序,找出请求/字符比最差的页。
5. 如果给了真实诊断 RTF/JSON:`abandonReason` 计数 × 块类型 × 像素盒尺寸交叉表,
   这是排版层唯一可信的优先级依据(2.7.3 就是这样把 43/52 的放弃归到一个根因的)。

把以上整理成一张"问题清单",每条:现象 → 证据(夹具名/页号/计数)→ 影响的用户
可见结果(英文残留 / 错译 / 多花 token / 慢)→ 你猜的根因(标"猜")。

## 第二步:挑批次(每批一个主题,≤3 个改动点)

排序依据固定为三个,依次权衡:

1. **用户可见的损失**:整段英文残留 > 结构错(表格熔格、正文进表)> 错译专名 >
   多花 token > 慢。
2. **证据强度**:真实诊断里复现的 > 多个夹具页复现的 > 单页 > 无夹具的推理。
3. **改动半径**:纯函数内的阈值/规则 > 新增一个纯函数 > 改流水线阶段边界 >
   改数据结构。半径大的必须给出为什么小半径做不到。

每个批次写成一页规格,格式固定:

```
批次 N:<主题>
证据:<夹具/诊断里的具体数字>
改动:<文件 :: 函数 :: 规则/阈值>,一句话说清"什么条件下做什么"
不该碰的:<反例 —— 哪类页面/块必须保持原样>,至少 2 个,最好指到具体夹具
预期快照变化:<列出会变的夹具名,其余逐字节不变>;基线变化同理
验证:<新增单测名 + 断言要点>
突变:<关掉/反转哪一行,期望哪个测试红>
回滚:<一行 revert 就能恢复吗?若不能,说明为什么>
```

## 执行规则(编码代理必须遵守)

- 一次只做一个批次;做完跑 `npm test`(不是 `node scripts/test.mjs`),再做突变
  验证,再写 CHANGELOG,再进下一批。
- 旧快照逐字节不变,除非规格里预告了它会变;变了的每一页要逐块 diff 审阅并在
  CHANGELOG 里按页写清"为什么是改进"。用逐夹具脚本核对,别只看测试红绿——快照
  测试在第一个不匹配处就停。
- 请求计划基线只能用 `UPDATE_BASELINE=1` 显式重生成,diff 进 CHANGELOG。
- 不删测试、不放宽断言来凑绿。测试期望值只在行为有意改变时更新,且在 CHANGELOG
  里说明。
- 隐私红线:原文/译文/密钥不进日志、不进 error.message、不进诊断;新加的任何
  日志字段都要能通过 `diagnosticsPrivacy.test`。
- 正文流不单独缩字;表格数字格/公式 preserve;译文不压未遮罩的墨迹——这三条不是
  可以"权衡"的参数。
- 不引入新依赖、不引入模型/ML 组件、不改 manifest 的版本范围。
- 阈值要有单位和来源(em、pt、px、比例),写在代码注释里,并引用触发它的夹具。

## 优先考虑的方向(按当前证据,可被你的第一步推翻)

- **结构恢复**:文本表长句列按视觉行碎成多格(radiology2023-p11);数据表整行
  预焊导致只有一条列带(chen2023-p10);正文段落被划进相邻表格区(wu2026-p6);
  均匀页的参考文献判定仍靠"序后即文献"。
- **排版恢复**:装了 2.7.3+ 之后的新诊断里 `abandonReason` 分布是什么——先看
  `shrink-floor/*+ink` 有多少,再决定要不要做"ink-blocked 正文的页级统一缩字"。
- **token 效率**:payloadChars 最高的页里有多少是重复块(dupBlocks)、表头/单位
  这类可以查表不必翻译的短格;系统提示能否按批次类型(prose/cells)裁剪。
- **执行能力**:`layoutMs` 高的页卡在哪一阶段;`attempts − requests` 大的页是
  哪个服务商在限流。

## 不要做的事

- 不要重写流水线、不要"引入布局检测模型"、不要把启发式换成大一统的打分器。
- 不要一次提交跨多个主题的改动。
- 不要在没有夹具复现的情况下改阈值;先把复现页转成夹具(corpus dump 即夹具格式)。
- 不要为了让某一页好看而改坏 34 页里的任何一页。

## 输出格式

1. 问题清单(带数字)。
2. 三到四个批次规格(按上面的固定格式)。
3. 你**不建议**做的事及理由(至少两条)。
4. 你对第一步数据的疑问 —— 哪些数字你觉得口径可疑、需要我确认。

先说结论,再给依据;不确定就说不确定;用中文。
