你现在要协助的项目是 **PaperMirror 文镜 for Zotero**(插件 id
`zotero-bilingual-reader@local`,当前版本 2.7.6),一个 Zotero 9/10 的 PDF 学术论文
双语翻译插件,TypeScript + esbuild,单人维护,BYOK(用户自带 API key)。先把下面的
背景读完,再回答我后面的问题;回答时默认我是这个项目的作者,不用解释 Zotero 是什么。

## 它做什么

打开一篇英文 PDF,插件把每页的文本层抽出来、还原成段落/标题/图题/表格单元格/
参考文献等结构块,按块送给翻译服务(OpenAI 兼容 / Anthropic / Gemini / 免费引擎),
然后把中文译文**原位排回页面**:两种模式——

- **覆盖原文**:在 PDF 页面上按原块矩形画遮罩,把译文精确排进原块的盒子里,
  版式、图表、表格数字全部保持原位;放不下的块诚实地保留英文原文,不叠印、不溢出。
- **对照翻译**:右侧窗格重建整页译文版面(第 N 页一张),与原文并排。

目标读者是临床/科研人员,核心价值是"读译文时版面和原文一模一样、数字和专名一个不错"。

## 流水线(文本层路径)

`buildBlocksFromSpans`(span → 行 → 段落,分栏检测 detectColumns + 分带栏归属
bandedColumnStamp)→ `orderBlocksForReading`(阅读序)→ `structureTableCells`
(表格检测 tableGuard:数值种子聚类 + 标题锚定文本表;网格建模 tableStructure:
列带/行带推断,格子分 text/data)→ `coalesceRegions`(段落合并)→ 请求计划
`planChunks`(正文流/单元格流两趟独立打包,字符预算 + 块数上限)→
`buildSystemPrompt/buildUserPayload` → 译文按块 id 回填 → `strictPageReplacement`
(行距/字距梯子 ladderFits → 无损扩边 pmExpandFit → 压缩重译 → 末位缩字
pmShrinkFit → 几何审计 pmGeometryAudit;每步都有墨迹闸和几何预校验)。

## 质量体系(改代码前必须知道)

- 34 个真实论文页面的**布局快照夹具**(`tests/fixtures/layout/*.spans.json` +
  `.snapshot.json`):每块的类型/栏/阅读序/表格行列/翻译模式/前 40 字。任何提取或
  结构改动,旧快照必须逐字节不变,除非改动是有意的、逐夹具 diff 审阅过、写进 CHANGELOG。
- **请求计划基线** `tests/fixtures/baseline/pipeline-baseline.json`:每页请求数、
  块数、字符数,同样规则。
- 931 个单测;**每个新触发条件/新机制都要做突变验证**(把它关掉,至少一个测试变红)。
- 真实诊断导出(只含计数/枚举,绝无原文/译文/密钥)是改进的唯一依据;放弃原因
  枚举 `abandonReason` 形如 `shrink-floor/height`、`expand-ink/none+ink`。

## 硬约束(违反即不可接受)

1. API key 不落盘到日志、不进任何导出。
2. 原文与译文永远不进日志和诊断(语料导出是用户显式授权的例外)。
3. 模型输出只能经 `textContent` 渲染,禁止 innerHTML。
4. 不许删测试或改断言来凑绿。
5. manifest `strict_min_version 9.0` / `strict_max_version 10.0.*`。
6. 正文流不单独缩字(相邻段落字号不一致=“发花”);只有标题/图题/单元格/微小单行
   可末位缩字,地板 8.5px。
7. 表格数字格、公式一律 preserve;参考文献默认 preserve(用户可在设置里打开
   “翻译参考文献部分”,这是有意的产品选项,不是漏洞);译文绝不能盖到未被遮罩的
   原文墨迹上。
