# 4.10 字体框范围与像素测量诊断

日期：2026-11-15。环境：Zotero 10.0.9 / Gecko 140 / macOS / DPR 2。结论：**继续保留 4.9 的字体框换算范围，不把 `deviceFontBox()` 扩展到所有字号。** 新候选重复出现的 1 像素读数不是可以忽略的单次噪声。

本文记录范围实验，不能充当 4.10.0 最终包的零裁切验收。后续合并修复、公开资产和随机审核数字见正式发布验证记录。

## 方法与候选身份

- 基线为公开 `4.9.0` XPI。
- 实验候选 `4.9.99` 从提交 `69f6c86` 的归档构建；除版本元数据外，生产逻辑仅删除字体框换算前的 `!consistent` 限制，不混入页眉页脚、符号字体和页面读取修复。
- 同一次 Zotero 运行内先测公开基线一轮，再测候选三轮。Gori 全部 10 页；Bae 2010 的缓存页为第 1–9、18–24 页，共 16 页。未把其余无本轮验收缓存的页算入。
- 每个提交块测量相位 `[0, 0.25, 0.5, 0.75]`。等待字体和布局稳定，分别截图 `overflow:hidden → visible → hidden`；亮度差阈值仍为 64，保留所有零值、非零值以及闭合前后差异。
- 全程只读既有译文缓存，打开阅读器前启用 `localOnlyMode`。实验结束恢复公开 4.9.0 与原设置；主运行和定向诊断均记录 `localOnlyRestored=true`、错误数 0。

## 定向截图与基线根因

另做两版本各两轮定向诊断，检查上述三块及一个只发生几何噪声标记的对照标题。每个目标记录逐字 `measureText`、256 px 参考字体框、Range 矩形、三态几何以及差分像素坐标和 PNG。两轮均重现同样读数；所有闭合前后图像差异为 0，所有目标均稳定且可见。

Gori 两个标题的 all-size 字号为 12.67 px、行高 12.6667 px，Range 字体框高 18 px。画布字体框为 14 + 5 = 19 px；参考字号换算后为 13.5 + 4.5 = 18 px。旧判断在字体框相差 1 px 时同时保留“从上量”和“从下量”的两种基线；all-size 替换让两种基线重合，失去该保守范围。

用这次实测“响”“访”的矩形和字形度量回放守卫，旧双基线结果上下各溢出 0.5 CSS px，因而不会在该排版档提交；替换后的单一基线结果却上下均为 0。实机截图在顶边发现漏墨，说明**只匹配字体框总高度不足以证明可以移除原来的基线不确定范围**。公开 4.9.0 继续尝试既有排版阶梯，两个标题最终使用 11.91 px 字号、13.5833 px 行高，并在四相位均无裁切。

另行检查了“8 个固定相位不一定覆盖所有连续滚动状态”的数学风险，构造出的窄危险区间确实能被固定采样漏掉。但把精确切换点枚举应用于本次 Gori 实测换算数据后，结果仍为 0，因此**不能把本次实机异常归因于采样间隙，也没有把该实验方案作为已验证修复合入生产守卫**。

`tests/unit/textInkBoundsScope.test.ts` 使用两块真实度量固定 4.9 的范围，防止再次直接去掉 `!consistent` 而重引入此问题；原有双基线测试保留。

## 区分真实裁切与测量标记

初版增强工具把 `scrollHeight/scrollWidth` 也纳入三态几何是否相同的判据，所以主运行原始 JSON 的 `noisyBlocks` 为基线 14、候选每轮 21。定向诊断证明，下列计量变化由切换 overflow 本身触发，并不是内容在截图间移动：

| 目标 | hidden → visible → restored | 实际矩形、字体与滚动位置 | 闭合图像差分 |
| --- | --- | --- | ---: |
| Gori 第 4 页标题 | `scrollHeight: 14 → 13 → 14` | 全部不变 | 0 |
| Gori 第 8 页 all-size 标题 | `scrollHeight: 16 → 15 → 16` | 全部不变 | 0 |
| Bae 第 21 页 4.9.0 “于” | `scrollWidth: 7 → 6 → 7` | 全部不变 | 0 |

工具 schema 3 因此分别记录 `rawGeometryStable`、绘制几何是否稳定、完整闭合状态是否恢复以及三态滚动范围。只有可逆的滚动范围计量变化不再单独记为噪声；矩形、字体、客户端宽高、滚动位置改变或闭合图像漂移仍阻止验收通过。所有非零像素照常保留，阈值未调整。

原始 JSON 未回写、未改计数，也没有把所有原 `noisyBlocks` 事后宣称为已排除；只有上述目标有逐状态证据。真实漏墨与计量变化可以同时存在：Gori 标题、Bae“于”的非零像素没有因计量变化而被删除。深色界面中隐藏状态像素接近背景色，开放状态变亮，说明白色字形被裁掉；亮度取绝对差兼容该配色。

Bae“于”的框宽 5.633331 px，而两版本的字形推进宽度均超过该宽度；差分像素位于右边，不是 Gori 的纵向字体框问题。该缺陷另行修正水平尺寸校验，并须由 4.10 候选 A/B 确认，本实验不冒充其修复后的验收。

测量工具回归见 `tests/unit/inkClipCheck.test.ts`：稳定零值、真实裁切、闭合漂移、缺页、未稳定、异常恢复、禁止放宽阈值、可逆滚动范围变化、开放期间真实位移以及“计量变化不能抹掉裁切”均有覆盖。
